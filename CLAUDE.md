# CLAUDE.md

Guidance for working in this repository. For a full feature/architecture reference, see [`docs/GalacticQuest.md`](docs/GalacticQuest.md).

## What This Is

**Galactic Odyssey** (codebase root: `Space Adventure`) is a browser-based, text-driven sci-fi RPG written in **vanilla JavaScript (ES6+ modules)**, HTML5, and CSS3. No build step is required to play — you open `index.html` in a browser. A build step exists only for version bumping, and Jest is used for tests.

The engine is deliberately **genre-agnostic**: a theme/vocabulary layer lets the same systems power fantasy, steampunk, superhero, etc. Generalizing the engine to other genres is a stated strategic goal.

## Commands

```bash
npm test           # Run the Jest suite (jsdom environment)
npm start          # Serve locally via http-server on :8080
npm run build      # node build.js — bumps patch version in package.json + data/version.js
npx jest tests/systems/combat.test.js   # Run a single test file
```

Per the user's global rules: **always run `npm test` before declaring a task complete.**

## Architecture

`game.js` is a thin **coordinator** — it imports every system and wires them together via **dependency injection**, then exposes the needed globals to `index.html`. It holds no game logic itself.

Three layers, strictly separated:

- **`systems/`** — all game logic (combat, quests, character, saveload, etc.). One responsibility per file.
- **`systems/ui/`** — presentation sub-modules for complex panels (dialogue overlay, dungeon raycaster, quest board, etc.). `systems/ui.js` coordinates screen/log/notification management.
- **`data/`** — pure data, **no logic** (enemies, items, locations, quests, recipes, cybernetics, companions, theme tokens, version).
- **`data/imagery.js`** — the image registry the viewscreen looks up. Keys are the game's own IDs (enemy `name`, boss/location/district `id`, dialogue NPC key). A missing key is an intentional fallback state, not a bug: the panel renders the caller's emoji instead. Art is generated by `npm run optimize-images` from the untouched masters in `assets/portraits/`; see [`docs/imagery_manifest.md`](docs/imagery_manifest.md).

Tests live in **`tests/systems/`**, one file per system, run under jsdom.

### Central state object

Game state hangs off a single `state` object; `state.character` is the core shape (see GalacticQuest.md §2 for the full schema). Key nested pieces: `equipment`, `inventory`, `activeQuests`/`completedQuests`, `ship` (module levels), `factions` (federation/corsairs/syndicate reputation), `npcs` (per-NPC disposition + `memoryFlags`), and `storyline` (act/alignment/variables). Save/load serializes this full object to LocalStorage (multi-slot) with JSON export/import.

## The Theme Engine (important before renaming anything)

Player-visible vocabulary is externalized so the engine can be re-skinned without touching logic:

- **`data/theme.js`** — the `theme` object of UI token strings. **This is the primary genre switch.**
- **`systems/theme-engine.js`** — exports `tToken(key)` for lookups and `applyThemeToDOM()`, which rewrites elements carrying `data-term="..."` attributes and can add a `theme-{name}` class to `<body>` for CSS overrides.
- `index.html` uses `data-term` attributes rather than hardcoded labels.

When adding player-facing text, prefer routing it through `theme.js`/data files rather than hardcoding genre-specific strings in logic. `docs/scifi_vocabulary_report.md` audits strings still hardcoded and is required reading before any generalization work.

## Conventions

- **Vanilla JS ES6 modules only** — no framework, no bundler, no TypeScript (JSDoc/TS migration is a pending idea, not current state).
- Keep logic out of `data/`; keep data out of `systems/` logic where a data file fits.
- New game logic gets a matching test in `tests/systems/`.
- Match existing module style; keep functions small and single-responsibility.
- Note: some paths in `docs/` use Windows-style `d:/source/...` links from the original authoring environment — the actual working tree is this repo root.
